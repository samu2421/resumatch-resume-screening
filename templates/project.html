Our Project

Automated Resume Screening System using Machine Learning and Flask

1. Overview

ResuMatch is a Flask web application. You upload a resume (PDF or DOCX) and enter a job title and job description. The app then shows:

  • the predicted job category (one of 25) with a confidence score, plus the three most likely categories with their probabilities,
  • the skills from a fixed skills list that occur in the resume,
  • the keyword overlap between the resume and the job description.

The app does not shortlist or reject candidates; the results are meant to support a human reviewer.

2. How it works

  • Text extraction: PyPDF2 for PDF files and python-docx for DOCX files. Only text-based files work; scanned images are not read. The upload is stored in a temporary file that is always deleted after processing.
  • Preprocessing (NLTK): lower-casing, keeping letters only, tokenisation (punkt_tab), removal of English stopwords (the words data, analysis, science, machine and learning are kept) and Porter stemming. Training and prediction use exactly the same preprocessing.
  • Classification (scikit-learn): TF-IDF features (unigrams and bigrams, at most 10,000 features, min_df=2, max_df=0.85) and a Logistic Regression classifier (class_weight="balanced"). The confidence score is the probability of the predicted category.
  • Skill matching: case-insensitive whole-word and whole-phrase matching against a list of 26 skills, including multi-word skills such as "machine learning".
  • Keyword overlap: the percentage of distinct job-description keywords (after the same cleaning) that also occur in the resume.

3. Data and evaluation

  • Dataset: the Kaggle "Resume Dataset" with 962 rows and 25 job categories. After removing exact duplicate resumes, 166 unique resumes remain.
  • Model comparison: Multinomial Naive Bayes, Logistic Regression and a linear SVM were compared with stratified 3-fold cross-validation on the 166 unique resumes (3 folds because the smallest category has only 3 unique resumes).
  • Selected model: Logistic Regression, with a mean accuracy of 0.85 ± 0.03 and a macro F1 of 0.80 ± 0.03 (3-fold CV). The linear SVM scored slightly higher but gives no probabilities, and calibrating it is not possible with so few resumes in the smallest categories. The model was chosen on the same folds, so these scores are slightly optimistic.
  • Hyperparameter tuning: tuning the regularisation strength, class weights and TF-IDF settings with nested cross-validation gave a macro F1 of 0.78 ± 0.04 (accuracy 0.84 ± 0.03), which is not better than the untuned model, so the untuned Logistic Regression is used.
  • Why not the earlier 95%: evaluating without removing duplicates gave about 95% accuracy, because almost every test resume had an identical copy in the training data.
  • Deployment of the model: the final model is trained on all 166 unique resumes, saved with pickle and loaded once when the app starts.

4. Technologies

Python, Flask, Gunicorn, scikit-learn, NLTK, pandas, PyPDF2, python-docx, pickle, pytest, and an HTML/Bootstrap template by HTML Codex.

5. Project structure

  • app.py – Flask routes and request handling
  • preprocess.py – NLTK setup, text cleaning, skill matching, keyword overlap, text extraction
  • train_model.py – deduplication, model comparison, evaluation and training
  • model/resume_classifier_pipeline.pkl – the trained pipeline
  • results/metrics.json – evaluation results
  • EDA.ipynb – exploratory data analysis
  • templates/, static/ – web pages and assets
  • tests/ – pytest tests

6. Limitations

  • The model is trained on only 166 unique resumes, so predictions for less common categories are unreliable.
  • Skill matching only finds skills from the fixed list.
  • Keyword overlap compares words, not meaning.
